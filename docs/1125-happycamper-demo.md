## What it does

HappyCamper's core utility is to merge two CSV rosters before performing a flexible set of checks, catching a wide range of problems that occur with algorithmically assigned camp activity schedules. 

Additional tools exist for more advanced analysis, but all operations treat the data as a big merged spreadsheet, meaning you can export your results at any time, and do whatever manipulations you want in the editor of your choice. 

HappyCamper is not meant to replace any tool or proven process, but work within existing systems to add a safety net and analysis surface. It was designed with extensibility in mind, and additions made since 2025 have proven this as an efficient and impactful pattern.

## future-proof

HappyCamper was built to outlast its developer. As a bundled java app, it has no external dependencies and is ready to run on any modern Mac, Windows, or Linux machine. The app is quick to download, then never needs the internet again. 

The biggest potential breaking point is the data it receives. The current implementation is adapted for a specific camp's input format, verified to work on schedules generated by their main camp app between 2024 and 2026. If camp details or roster formats change, the app would need to be updated. As an open source app with strong internal documentation and intuitive logic, any future changes of this sort will be easy to make. 

## free and open source

As an open source project, HappyCamper is easy to access, audit, and trust. Your data always stays local, but how the app itself works is always traceable. You don't have to my word on anything written here, the code speaks for itself.

This makes it accessible to others down the road, for future developers (or any idiot with a claude code subscription) to adapt and extent to meet their camp's needs. I'd love to share more with anyone who's interested: reach out to jaymorandev@gmail.com with further questions or ideas.

## offline and trustworthy

The app is designed for data safety: it can't reach the internet, all file imports and exports are manual user actions, and no roster data is stored between runs.

After the original app was built and tested, I introduced agentic coding tools to improve test coverage and perform more efficient structural revisions. All data used for testing and reference was anonymized or fabricated long before it touched a public repo or an agentic system.

As a developer I lean stubbornly against AI-driven development and "vibecoding". The core HappyCamper app was developed long before this was a productive way to work, and I take pride in HappyCamper's internal logic, extensible design, and the human effort that went into this tool's creation.

## History

### 2024 - Validation script
As a seasonal camp leader, I observed teammates spending hours combing through auto-generated schedules to catch common errors before they burnt us the next day. In the fall, I wrote a command line script to crosscheck these rosters, turning a tedious review sequence into an instant, reliable utility.

### 2025 - Desktop app

In advance of summer 2025, I developed this tool into a more user-friendly Java app, extending it from a simple cross-checking tool to highlight a longer list of common schedule issues.

HappyCamper v2.2 debuted in May 2025 to rave reviews, saving our leaders precious hours each week and ensuring better camper experiences from day one.

### 2026 - Analysis platform
After more collaboration with seasonal leaders, I implemented a wishlist of additional features, helping activity coordinators do more with the data we already have. 

Versions 2.3 to 2.5 deployed throughout the summer, adding pass/fail checks, flexible search and sort controls, advanced preference analysis, and configurable views for custom workflows.

### Future Work

- Better tutorials: in-app help buttons and walkthroughs are a current weak point. The current user group strongly preferred functionality before fancy buttons, and most features are still used primarily by the very people that conceived of them. This means that the new features have outpaced the app docs and tutorials, and are high on my list of pending improvements.

- Browser edition: I would love to develop a lighter, browser-based implementation of this tool, lowering the barrier of access while remaining serverless. If you're a nerd, my scheme is a single-page html file with typescript logic, accessed as a serverless static site and shareable as a file to open in any browser.

Further development of this app is paused as I prioritize other projects, but these remain goals before Summer 2027.
