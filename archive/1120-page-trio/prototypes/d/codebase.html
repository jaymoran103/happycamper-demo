How it's built

Four short answers for anyone deciding whether to trust it with their rosters.

  1. What it does
  2. Where it runs

What it does

  1. ImportTwo spreadsheets saved as CSV files: your camper list and your activity schedule.
  2. CheckHappyCamper merges them into one table, with filters for finding errors in it.
  3. ExportSave the merged table as a CSV to work on in your own spreadsheet tool.

Where it runs

HappyCamper is a download that runs entirely on your computer. Here's what's in it.

Your rostersopened from and saved to your own folders
HappyCamperthe app
Javaincluded in the download, nothing else to install
Mac, Windows or Linuxruns the same on each

Your data only crosses into the app when you import a file, and only leaves when you export one. It never goes online.

The web demo on this site works the same way in your browser, with built-in sample data. A typical website is different: it runs on the company's servers, and what you enter is sent there.

How it came to be

It started in 2024 as a script for checking camp activity schedules for mistakes. In 2025 I rebuilt it as a desktop app, designed and written entirely by hand, and camps used v2.2 that summer. In 2026, versions 2.3 to 2.5 added what users asked for: pass/fail checks, sorting by demand, saved views and activity reports.

The rosters in the code were written by hand or anonymized with NameSwap before the project touched a public repository or an AI tool. From spring 2025, AI tools helped me improve test coverage and make large internal changes efficiently.

Next is a browser version that still needs no server, so it can be shared and opened anywhere while your data stays on your computer.

Where the code lives

The code is public on GitHub, a site that stores code along with the history of every change. Anyone can read it without an account, and a developer can build it with standard Java tools.
