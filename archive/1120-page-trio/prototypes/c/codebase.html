HappyCamper How it's built

A desktop app that checks camp activity schedules. It runs on your own computer, never goes online, and its code is public.

What it does

HappyCamper takes two spreadsheets saved as CSV files, your camper list and your activity schedule. It merges them into one table and gives you filters for finding errors in it. To work in your own spreadsheet tool, export the merged table.

Everything runs on your computer

Data only goes in when you import a file, and only comes out when you export one. Nothing is kept between runs.

The download includes Java, the language HappyCamper is written in, so there's nothing else to install, and it runs the same on Mac, Windows and Linux. For a developer, the code builds with standard Java tools.

How it came to be

  1. 2024

    A validation script

    A script for checking camp activity schedules for mistakes.

    Data first. Real camper data never went into the code. Every roster in it was written by hand or anonymized with NameSwap, before the project touched a public repository or an AI tool.

  2. 2025

    A desktop app

    I rebuilt the script as a Java app, designed and written entirely by hand. From that spring, AI tools helped me improve test coverage and make large internal changes efficiently as I refactored it into v2. Camps used v2.2 that summer.

    happycamper-public · v2.2
  3. 2026

    An analysis platform

    Versions 2.3 to 2.5 added what users asked for: pass/fail checks, sorting by demand, saved views and activity reports. The downloads on this site come from here.

    happycamper-heart · v2.3 to v2.5
  4. Next

    A browser version

    The same app as a page that still needs no server, so it can be shared and opened anywhere while your data stays on your computer.

Both repositories are on GitHub, a site that stores code along with the history of every change. They're tested, reviewed, and usable today, and anyone can read them without an account.
