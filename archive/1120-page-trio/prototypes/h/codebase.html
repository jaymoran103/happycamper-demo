How it's built

What the app does with your files, why it runs the way it does, and how it came to be.

Built on spreadsheets

At its core, HappyCamper merges two tables into a more helpful one, then gives you good tools to analyze it and make impactful revisions. The user experience closely matches other table viewers. If you're a spreadsheet wizard, just export the merged CSV and use the new columns to do your own magic in another editor.

Secure and open source

As an open source project, HappyCamper is easy to access, audit, and trust.

The app is designed for data safety: it can't reach the internet, file imports and exports are manual user actions, and no roster data is stored between runs.

Free and future proof

I picked this stack to prioritize flexible access: as a standalone app it is quick to download, then never dependent on an internet connection or update again. The core logic is simple and extensible, ready to be modified to suit new camps or new needs.

History

2024. A script for checking camp activity schedules for mistakes.

2025. I rebuilt the script as a desktop app, designed and written entirely by hand. From that spring, AI tools helped me improve test coverage and make large internal changes efficiently as I refactored it into v2. Camps used v2.2 that summer.

2026. Versions 2.3 to 2.5 added what users asked for: pass/fail checks, sorting by demand, saved views and activity reports.

Next. The same app as a browser page that still needs no server, so it can be shared and opened anywhere while your data stays on your computer.

Real camper data never went into the code. Every roster in it was written by hand or anonymized with NameSwap, before the project touched a public repository or an AI tool.
