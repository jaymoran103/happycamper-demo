How it's built

What the app does with your files, why it runs the way it does, and how it came to be.

How the app works

You start with two spreadsheets saved as CSV files: your camper list and your activity schedule. HappyCamper merges them into one table and gives you filters for finding errors in it. When you're done, export the table as a CSV to open in any spreadsheet tool.

Everything in that picture happens on your computer. HappyCamper never connects to the internet, and nothing is kept after you close it. Data only goes in when you import a file and only comes out when you export one.

Because the files are plain CSVs, HappyCamper works beside whatever you already use. Download your rosters from wherever they live, check them here, and upload the export back if you need to.

Unlike a website, there's no server to keep running and no account to make. The download includes Java, the language HappyCamper is written in, so it needs nothing else installed and runs the same on Mac, Windows and Linux. It keeps working as long as you keep the download, and because the code is public, another developer can pick it up with standard Java tools.

I designed and wrote the app by hand. The rosters in its code were written by hand or anonymized with NameSwap before the project touched a public repository or an AI tool. From spring 2025, AI tools helped me improve test coverage and make large internal changes efficiently.

Both repositories are on GitHub, a site that stores code with the history of every change. They're tested, reviewed and usable today, and anyone can read them without an account. The downloads on this site come from happycamper-heart.
